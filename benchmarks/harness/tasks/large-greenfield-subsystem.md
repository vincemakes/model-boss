Build a complete shopping-cart subsystem for this TypeScript project.

Create exactly these eight modules under `src/cart/` (one file each, ESM, strict TypeScript):

1. `types.ts` — shared types: `Money` (integer cents), `Sku`, `LineItem { sku, quantity, unitPrice }`, `Cart { id, items, couponCodes, currency }`, `PricingBreakdown { subtotal, discounts, total }`, `Coupon { code, kind: "percent" | "fixed", value, expiresAt }`, `CartEvent` (a discriminated union covering item-added, item-removed, quantity-changed, coupon-applied, coupon-removed, cart-cleared, each with `seq: number` and `at: number`).
2. `errors.ts` — a `CartError` base class plus `OutOfStockError`, `CouponExpiredError`, `UnknownCouponError`, `InvalidQuantityError`, `CorruptPayloadError`, each carrying a stable string `code`.
3. `cart.ts` — `createCart(id, currency)`, `addItem`, `removeItem`, `setQuantity`, `clearCart`, `applyCoupon`, `removeCoupon`. Quantities are positive integers; `setQuantity(…, 0)` removes the line; invalid quantities throw `InvalidQuantityError`. Every mutation returns a new cart (no in-place mutation) and appends one event via `events.ts`.
4. `pricing.ts` — `priceCart(cart, coupons)` producing a `PricingBreakdown` with volume tiers per line: 1–9 units full price, 10–49 units 5% off that line, 50+ units 12% off that line. Coupons apply after tiers: `percent` coupons discount the post-tier subtotal, `fixed` coupons subtract cents and never push the total below zero. All arithmetic is in integer cents with round-half-up.
5. `inventory.ts` — `createInventory(initialStock)`, `available(sku)`, `reserve(sku, quantity)`, `release(sku, quantity)`. Reserving more than available throws `OutOfStockError` and leaves stock unchanged; release never exceeds the original stock.
6. `coupons.ts` — `createCouponBook(coupons)`, `lookup(code, now)`: unknown codes throw `UnknownCouponError`, codes whose `expiresAt <= now` throw `CouponExpiredError`; `isExpired(coupon, now)` helper.
7. `events.ts` — `createEventLog()`, `append(log, event)`, `eventsFor(log, cartId)`, `replay(events)`. `seq` is strictly increasing per cart starting at 1; `replay` rebuilds a cart from its events and rejects out-of-order sequences with `CorruptPayloadError`.
8. `serialization.ts` — `serializeCart(cart): string` and `deserializeCart(payload): Cart`. Deserialization validates the shape and throws `CorruptPayloadError` (with a message naming the bad field) on malformed JSON, missing fields, wrong types, negative quantities, or unknown currency codes.

Add at least 40 test cases under `tests/cart/` (vitest, `*.test.ts`) covering happy paths and these edge cases explicitly: tier boundaries at exactly 9, 10, 49 and 50 units; percent and fixed coupons including a fixed coupon larger than the subtotal; an expired coupon and an unknown coupon; reserving more than available stock; releasing back to the original stock; corrupt serialized payloads (bad JSON, missing field, wrong type, negative quantity); strictly increasing event sequence numbers; and replay rejecting out-of-order events.

Constraints: do not modify any existing file outside `src/cart/` and `tests/cart/`; do not add dependencies; do not touch `package.json`, `tsconfig.json`, or `vitest.config.ts`. Both `pnpm typecheck` and `pnpm test` must pass when you are done. Finish with a short summary of what you built and the final gate results.
